# 记忆整理与缓存

确认后维护、来源证据、更正和预算的实现参考。云端长期整理本机仍关闭；当前验收状态见[交接页](../../context-memory-implementation.md)。

## 确认送达与记忆来源

沿用同一个 inbox/outbox 和唯一发送确认路径。确认送达后才归档机器人回复、持久保存
分类阶段有图片输入证明的描述，并刷新本会话的关键词/向量索引。没有新接收或发送循环。

现有唯一 self 回读只缓存最后一个精确原生行，不另查聊天或按正文猜测。核心先将这条
原生消息及 receipt 写入本地 proof，再应用既有持久 ACK；归档仍核验账号、会话、原请求、
唯一 outbox、正文和 receipt。proof 自身不能把 UNKNOWN 变成 ACK，也不能授予发送权限。
若 ACK 后本地维护失败，空闲时仅补做本地维护，既不再请求模型，也不再次发送。
没有完成 ACK 的 proof 保留审计，不能进入记忆。原生消息 ID 与事件身份算法不变。

`unified_memories` 保存带来源、作者和版本的事实、偏好、事件与约定。
`unified_supersessions` 追加更正关系，不覆盖原始消息或旧记忆正文。
分类明确判为更正、且回复确认送达后，可用用户当前原文创建更正；不把回答模型的改写
当作用户事实。同作者才能替代旧记忆，群其他成员不能直接覆盖别人的偏好。
选中旧原文而没有旧记忆时，先保存其来源版本，再追加更正版本。

每次读取记忆都重新核验完整 scope、作者、原消息哈希及来源观察快照。来源变更、丢失、
观察到期或被更正后，旧证据立即失效，缓存和旧向量不能恢复它。
新增观察也会保守地使旧来源快照失效；这可能少召回，不能静默信任旧摘要。
旧版本仍可按精确 ID 本地检查，但不作为当前事实回答。普通原文和来源长期保留。

派生记忆与原始混合检索共同提供有限候选：优先精确引用，最多 6 个派生候选，合计不超过
20 条及配置长度。记忆候选按关键词和已有 CUDA worker 语义匹配；每轮最多检查 32 个
派生条目/128 个模型块，其余报告部分检索。来源资格、作者、scope 和版本还会在回答组装
时再次校验。更正通过 `CorrectionNotice` 附在候选上，不屏蔽整个原始消息，
不必等待 sidecar 重建。明确引用旧说法时可以回顾当时原文，当前事实采用有效的最新更正。
片段级更正只关联对应 `SourceRef`；旧数据只有消息级来源时标注“此消息存在更正”，
不能推断其他片段也失效。附带展示的最新更正不自动成为下一次更正的目标。

分类阶段看到原文和更正关系；回答组装再次查询并校验完整更正链。
链长最多 32 个替代版本，单轮最多 6 条更正说明，全部计入候选长度和模型上下文预算。
链路循环、跨账号/会话、作者不符、数量超限、说明无法完整放入预算时，相关请求进入澄清，
不单独提供旧说法作为当前事实。最新版本的证据失效时返回 `latest=null`，回答须说明
有效更正不可用，不能恢复旧说法。图片仍经附件层校验；历史引用和更正都不能重取过期原图。
观察到期只使对应派生记忆/观察失效，原文、URL 和其他内容片段仍可独立检索。
GPU 故障时保留关键词路线并报告降级，不静默切换 CPU 模型。

## 空闲整理与预算

只有显式开启新整理开关才调用云端；运行在现有串行 processing operation 的空闲分支，
不新增后台模型任务。暂停、目标暂停、账号未就绪或有待处理 inbox/outbox 时不得付费整理。
每个 scope 必须已有确认送达记录，默认至少积累 20 条尚未整理的消息；普通群消息不逐条
调用模型。正在发送、失败或 UNKNOWN 回复所关联的入站消息不合格。

- 每会话最多每小时一次，跨重启保持。
- 全部 scope 合计每天最多 0.50 元，使用主配置时区划分自然日。
- 整理调用同时经过原全局 5 元/日、100 元/月预算，不是额外赠送额度。
- 一个无工具、不思考的 DeepSeek Flash 请求，最多 8192 输入/512 输出 tokens，最多 6 条结果。
- 请求前持久登记任务与最大估算费用；成功后以返回用量和配置价格结算本地子额度。
- 格式/来源非法、超时、取消或进程中断不自动重试该批；保留最大估算额和任务来源。
  残留 started 表示结果可能不确定，和 unknown 一样不可自动重跑；不要手动删行后重试。
- 预算不足时不绕过全局预算。整批结果及更正关系在一个事务内保存，不部分应用非法输出。

整理请求使用不可变 `EvidenceSnapshot`，与实际请求的消息、观察及记忆目录由同一份
输入构建，记录来源指纹、观察 ID/指纹/有效期以及记忆版本。结果提交时在写事务内
校验请求快照，再原子写入整批记忆及更正；批次应用后再次核验来源及目录记忆的有效期。
本批次有意替代的目录版本仍需校验原证据，不能因 inactive 状态跳过有效期检查。
源消息变化、观察被修改/删除/过期、目录记忆被更正或失效时，报 `MemoryEvidenceChanged`，
整批结果不写入。任务记为终态 `rejected`，保留来源并按已知用量结算本地子额度，
和 `done`、`unknown`、遗留 `started` 一样不自动重跑。原费用账本照常记录实际模型调用。
快照只保存在本次调用内；进程中断沿用不重跑规则，不需要新增 schema 或迁移。
成功记忆保存请求时的证据指纹，后续过期依然失效，不能把已过期正文降格为 URL 证据。

当前整理窗口最多读取最近 1000 条原始记录，每个 scope 最多检查 1000 条派生记忆。
整批超过输入上限时明确不调用，不静默截断来源；大消息批次/大存档仍需阶段 7 的诊断与
后续容量方案。本阶段没有自动回填旧聊天或批量整理历史。

## 缓存与统计

内容缓存以完整来源消息哈希、提取版本和内容摘要为键，并绑定同一 scope/part。
它复用已验证的网页正文或已确认的图片描述；命中后仍查原观察是否存在、有效。
不会凭哈希访问其他会话，也不会把失败页面、过期原图或占位当成可见图片。
网页缓存复用的是同一归档消息的提取结果，不将旧 URL 变成新的浏览授权。

向量复用阶段 3 的模型/后端/精度/查询类型/文本版本缓存与阶段 4 的 sidecar 向量；
派生记忆也经过同一 worker 缓存边界。主题目录按批次版本保存，每 20 条消息完成整理后
更新；纠正或来源失效立即使旧目录失效。目录是本地整理辅助，不自动塞入每个回答。

分类、回答和整理的固定系统前缀保持不变；历史目录在前，增量证据、时间与原始问题后置。
不为缓存命中添加无关历史，不保证两阶段比单次请求便宜。

`unified_stage_usage` 区分 classification、answer、tool:* 和 consolidation 的用量、耗时、
已报告的缓存命中 tokens 与本地估算费用。未命中为 prompt − cached；模型结果不确定时
单独标记并保守显示最大可能费用。预算账本仍是额度控制来源，供应商账单仍独立。
当前只读本地搜索/时间/网页工具无服务调用费用，记录耗时，不将模型续轮费用算到工具。
嵌入 worker 的 stats 继续提供本地向量缓存命中/未命中和推理批次数。

本机只读汇总入口要求显式指定**已迁移的测试库或备份**，不会创建或升级数据库，不输出
账号 ID、原文、来源文本或凭据：

```bash
uv run --locked python -m lemonbot.memory.unified.stats_cli --database "$LEMONBOT_ARCHIVE_COPY"
```

## 配置与下一步

所有可编辑配置仍在仓库 `config/lemonbot.toml`。示例及本机实际开关保持关闭：

```toml
[context_memory]
enabled = false
archive_enabled = false
consolidation_enabled = false
consolidation_min_messages = 20
consolidation_daily_cny = "0.50"
```

整理开关要求新上下文开启，旧 `wechat_agent.memory_enabled` 必须关闭。
本阶段只在临时数据库验证增量迁移 `20261015_0008`；没有迁移生产数据库。
新表独立追加，不重建旧表、不清除 UNKNOWN；降级拒绝删除新存档，回退使用配置/代码回退。

下一步是阶段 7：全链路离线验收、迁移与恢复演练、完整 doctor/状态/来源检查及部署准备。
本阶段不部署、不重绑、不测试真实模型或微信。
