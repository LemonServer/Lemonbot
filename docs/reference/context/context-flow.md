# 两阶段分类与回答

新流程的分类、来源校验与回答实现。公开默认关闭，本机部署和验收状态见[当前交接](../../context-memory-implementation.md)。

## 流水线

既有 `EventPipeline` 先执行暂停、白名单和策略检查，新分支才会工作：

1. 从 broker 绑定的账号/会话 map 精确读取当前归档消息，核验 event ID、作者和时间。
   当前问题沿用原 Message 的文字、图片、链接、卡片及引用结构；不从旧 recent_messages
   拼接对话，也不调用旧 ContextBuilder/长期提取器。
2. 调用阶段 4 的混合检索。分类阶段看到原始当前消息和有限候选；当前图片或唯一明确
   引用的图片在附件可验证时可以提交给分类模型，无引用的历史图片不会自动上传。
3. 第一次模型请求前，使用共享持久预算预留分类和首次回答两个请求的最大费用。
   分类使用 DeepSeek Flash，`deep=false`、无工具、温度 0、最多 512 输出 tokens。
4. 分类返回 standalone、related 或 clarify，最多 6 个候选 ID。程序严格解析 JSON，拒绝
   重复字段/ID、NaN、额外字段、错误类型、矛盾模式及未提供的 ID；不接受改写后的问题。
5. 程序重新读取来源，核验 scope、消息资格、作者、时间、part、observation、来源片段和
   有效期，再构造 ContextBundle。独立问题只携带当前输入；关联问题才携带选定证据，
   历史片段明确标注作者、时间与来源，不自动附加整段聊天。
6. 回答仍调用原有 `_run_model_and_tools`，共用原收发队列、策略、工具权限、费用和串行路径。
   不新增发送方法。最终仍是一条持久 outbox 任务，一次 POST 和唯一 self 回读确认；
   UNKNOWN 不重发，重启不补处理停机消息。

代码入口：[flow.py](../../../src/lemonbot/memory/unified/flow.py)、
[assembly.py](../../../src/lemonbot/memory/unified/assembly.py)、
[pipeline.py](../../../src/lemonbot/orchestration/pipeline.py)。

分类请求采用普通文本响应并要求仅输出 JSON，由程序执行严格校验。这样，已完成且用量
明确的请求即使返回损坏 JSON，也能回退而不把它与传输/IPC 不确定混为一谈。
它不是自由文本分类，也不因格式无效再次请求分类。真实 DeepSeek 格式仍待阶段 8 验证。

分类输入过长时先减少可选候选，只允许选择实际送入分类请求的 ID；不截断原始当前消息。
当前消息本身无法容纳时，在付费前明确停止。回答同时为现有工具 schema/结果预留空间；
选中证据无法容纳时回退当前问题或澄清，仍不静默改写原文。

## 图片来源与上下文

新分支每次请求最多一张原图：新当前图片优先；历史图片必须由分类模型明确选中其候选，
并提供精确到 part 的 SourceRef。引用某条消息的文字不能借用同消息的图片。
普通换题即使检索出现图片描述，也不会自动携带最近一张图。

[BoundImageResolver](../../../src/lemonbot/memory/unified/images.py) 复用已有持久 inbox 和附件表，
无需新增数据库 schema 或复制附件：

- 精确匹配账号/会话中的源消息、image part 和 `image_source_ref`；来源只能是已验证
  WAL 取图流程登记的附件，哈希本身不能授予访问权限。
- 优先当前精确取图事件或原始事件。两者都不存在时，按完整来源找既有取图记录；
  无法唯一确定就拒绝，不挑 first/latest 隐藏歧义。
- 对引用图核验取图事件的归档引用关系，核验 UUID 对应的 channel/chat/event、媒体类型、
  文件大小、保留期限和 SHA-256。核心流式验证内容，只向 worker 传受控对象引用。
- 模型 worker 继续在私有对象目录重复验证、解码、缩放及清理元数据，只在 HTTP 构造时
  生成 Base64。IPC 仍为 1 MiB，没有跨进程传大段图片或提高帧限制。
- worker 通过 `ModelResponse.image_input_accepted` 报告实际是否构造了图片输入块，
  该值由网关计算，不能由模型正文声明。只有明确图片输入证明才接受分类产生的图片观察。
- 回答每次模型请求前再次核验选中的图片；过期或损坏时去掉原图并标注不可见。
  原图过期后可引用仍有效、明确标注的历史描述，不能声称看过过期原图。

没有安全取得/保存过的普通群图片只保留占位，不因检索或分类自动下载。
明确引用的图片沿用当前连接器授权的精确下载链路。旧数据没有合格取图来源时明确不可用，
不通过正文相似、昵称或最近文件猜测。图片观察此阶段只在本轮 bundle 中使用；
确认送达后的持久复用和索引即时更新已由默认关闭的阶段 6 接入。

## 预算、工具和失败处理

[PrepaidPair](../../../src/lemonbot/models/prepaid_budget.py) 使用既有 BudgetManager 和持久账本：

- 两个初始请求各按配置上限（最多 8192 输入、512 输出，图片各按既有 1024 token 估算）
  预留；图片计入输入 token 上限，不将 Base64 长度当文本 token。
- 现有网关/隔离 proxy 按同一任务和同一 budget manager 消费已留额度，逐次正常结算，
  不重复插入预留或重复计费。配额不足以覆盖两个请求时，首次云端调用不会发生。
- 未消费的额度在正常完成、前置失败或取消时释放。进程崩溃遗留的 reserved 行仍由既有
  恢复逻辑按全额 unknown 保守计费，不删除历史 UNKNOWN 或账本。
- 子任务不能借用父任务的预留，其他 provider/model 不消费这两个额度。跨日期/月、
  估算超上限或预留失效时拒绝调用。日/月预算沿用主配置（当前 5 元/100 元）。
- 分类消耗计入原 pipeline 的模型轮数和任务 token 限制；回答不启用 /deep。
  带图分类和带图回答分别计算图片用量。供应商账单与本地估算仍需区分。

无工具的普通回复是一次分类加一次回答。回答阶段如需要工具，会沿用既有、有界的模型/
工具循环；其后续模型请求另行正常预留和结算，因此有工具时不保证总共只有两次 API 请求。
首次分类和首次回答仍在任何云端请求前完成两阶段预留。

分类没有工具。回答仅保留既有 web.read、web.search、clock.now 的授权和限额。
只有当前用户原文 URL 或本轮登记的搜索结果 URL 能授权浏览；历史 URL、网页和图片文字
不产生新权限。共享卡片仍通过 broker 提供的精确字段按原路径读取。
工具执行不引入接收重入或额外导航/发送路线。
当前原文链接或卡片的读取结果会按精确 URL、消息和 part 保存为来源 Observation，
后续追问可检索正文；失败只保存不可用原因，不把验证页当正文。相同调用重复保存幂等。
这属于原始来源观察，不是已送达的 assistant 历史或记忆提取。
搜索派生页面的独立归档来源留待后续，不伪装成当前消息原有链接。

无效分类不自动重试：独立且可理解的问题只用当前输入回答；依赖缺失引用或先前内容的
问题要求简短澄清。无效/过期/变更的来源不部分混入上下文。
传输、IPC、模型身份、用量或预算不确定时停止后续付费调用；新分支错误始终不可自动重试。
暂停或目标不可处理时不得进入分类或回答 I/O。

## 配置与后续部署边界

可编辑配置仍在仓库 `config/lemonbot.toml`，白名单仍由它引用，密钥留在系统密钥环。
本次实际文件没有改写，以下开关保持：

```toml
[context_memory]
enabled = false
archive_enabled = false
```

实现已允许在符合条件的模拟/后续部署环境显式启用：必须是已绑定的 conversation runtime，
archive 同时开启、旧 `wechat_agent.memory_enabled` 关闭、模型轮数至少 2，继续沿用
现有 budgeted DeepSeek Flash 与 token 上限检查。启用分支创建私有
`data_root/context-index/<profile>/index.sqlite3`，复用独立 CUDA worker；默认关闭不创建索引或 worker。
GPU 无法使用时显式降级为阶段 4 的关键词/近期检索，不静默改用 ARM CPU 模型。

首次启用须完成备份、迁移和有限实机验收；已部署的本机不重复执行迁移。
回退通过关闭新开关和安全重启，保留所有状态。

## 验证范围

离线用例使用临时数据库、模拟模型及 HTTP Mock，不调用真实 API 或发送微信。
后续真实 API/微信验证单独记录在当前交接，不与模拟结果混同。
覆盖文本关联/独立、图片追问/换题、精确引用图、附件篡改/失效、分类期间观察失效、
候选裁减后 ID 成员资格、作者/片段核验、无效 JSON、预留与单次结算、额度跨重启、
取消/崩溃/日期切换、历史 URL 不授予工具权限、暂停和 UNKNOWN，以及默认关闭的兼容性。
运行统计与阶段状态见 [实施记录](../../context-memory-implementation.md)。

本阶段没有提前启用长期整理、主动消息或不 @ 接话。
