# testing 群非 OCR 身份路线实机调研

首次观测：2026-09-09；复核进度：2026-09-10。代码基线为 `f96d479` 加当前工作树修复，
官方微信 4.1.1.8，本地活动、未锁屏的 GNOME Wayland 会话。用户授权范围为 `testing` 群。
汇总事实见 [脱敏证据](../evidence/atspi-identity-20260909.json)。

> 归档说明（2026-10-08）：本路线暂停开发；当前主线与版本见
> [文档索引](../README.md)和[环境基线](../environment-baseline.md)。以下结论适用于注明的原生微信环境。

## 已得到的结论

**资料卡的 `Weixin ID` 字段可通过 AT-SPI 直接读取，不需要 OCR。** 当前资料卡由操作者点击
消息头像打开；自动从消息定位并打开对应资料卡尚未证明。这两个结论必须分别记录。

| 检查对象 | 实测结果 | 含义 |
|---|---|---|
| testing 聊天公共子树 | 210 个节点，遍历未截断 | 当前可访问结构已完整检查到设定范围 |
| 独立 `get_accessible_id()` | 210 次读取成功，全部空值 | 没有在该子树找到可复用的独立控件标识 |
| `get_attributes()` | 所检节点均无属性 | 原属性探针没有遗漏同一子树的非空属性 |
| `get_relation_set()` | 210 次读取成功，仅两个输入框滚动条有关系 | API 能返回关系，消息行则没有关联证据 |
| 7 个消息行 | 无子节点、无动作、无关系 | 没有可直接调用的消息头像控件或资料卡关系 |
| 人工打开的资料卡 | 存在独立弹层，标签与值分别为同级 label | 可直接读取 `Weixin ID`，昵称 OCR 不再是唯一候选 |
| 资料卡可见结构 | 访问 147 个节点，跳过 50 个隐藏节点，报告 97 个可见节点 | 可见范围遍历完成；不宣称隐藏结构已穷尽 |
| 资料卡独立 ID/关系 | 所报告可见节点均无独立 ID、无关系 | 尚未发现指回原消息的语义关联 |

两条关系的类型为 `CONTROLLER_FOR`（3），来源是输入框内部滚动条，符合滚动条控制视口的
语义，不能解释成发送者关联。头像即使在屏幕上可见，也没有因此成为消息行的可访问子控件。

## 资料卡读取方法与局限

在操作者已打开资料卡的前提下，确认后台仍为 `testing`，检查唯一弹层；在其可见非列表、
非输入框结构中匹配固定标签 `Weixin ID` / `WeChat ID` / `微信号`。本次找到的标签与值是
同一父节点下的两个 label：标签位于索引 0，非空值位于索引 1。

原始值只用于进程内加盐摘要比较，不输出或写入报告；盐不落盘。摘要只适用于同一比较进程，
不同探针运行的摘要不能直接比较。只读脚本没有调用点击、聚焦、发送或资料修改接口。

最初两次资料卡检查触及 1000 节点上限，不能作为“字段不存在”的证据。随后缩小到独立弹层、
去重并跳过隐藏分支，才完成可见范围检查。初始固定词表仅覆盖 `WeChat ID`，补充实际界面的
`Weixin ID` 后识别出字段；原始字段值始终未输出。

`Weixin ID` 可读并不证明它不可变，也不证明自动消息归属已经成立。尚需分别验证：

- 同一成员跨更多资料卡重开轮次是否保持一致（一轮已经通过，见下）。
- 两个不同成员是否产生不同字段值；缺失或重复字段时是否拒绝。
- 微信重启、改名及账号标识变化后如何重新登记。
- 自动操作如何从具体消息绑定到资料卡，而不是仅依赖操作者刚打开了谁。

### 重开与进程隔离复测

操作者确认已关闭并重新打开同一成员资料卡。原比较进程保留了重开前的内存摘要，但第二次
读取长时间不返回，已终止；具体阻塞调用未定位。因此没有得到重开前后字段值一致的机器证明。

随后对当前已重开的卡片启动两个独立只读进程，每个进程限时 45 秒，使用同一个仅驻留比较
进程内的随机盐：两次读取均完成，字段值摘要与字段结构均一致。该结果证明新进程读取可用、
同一张已打开卡片的两次值一致，不能代替跨资料卡重开的比较。后续生命周期实验应采用独立
短生命周期子进程，避免在等待操作者期间持有旧 AT-SPI 对象。

继续采用独立子进程重做完整重开实验：读取当前成员后退出第一个子进程，操作者确认再次从
同一成员消息头像重开资料卡，再启动第二个子进程。结果为 `same_value=true`、
`same_field_structure=true`，**一轮人工确认的同成员重开对比通过**。这次比较不依赖先前失败
进程的摘要；也不等于微信重启、换号或自动消息归属已经验证。

不同成员对比未执行：操作者反馈暂时没有另一成员可供比较，比较器在取得第一个样本后主动
取消，未读取第二个对象。取消结果不能记为字段不稳定或不同成员相同。

## 当时的下一步选择（当前暂停）

优先研究“人工确认资料卡登记 + 可审计的局部消息绑定”。如果最终需要图像几何定位头像，
它属于单独待验证的动作路线，不能把已有累计消息矩形直接当作头像点击坐标。当前没有这样的
几何证明，故本轮没有自动点击头像。

暂停继续调优昵称 OCR；它不能补出消息与资料卡之间缺失的关联。保持 enrollment、runtime、
模型与 outbox 门禁关闭，不将控件 ID、显示名或本轮摘要当作管理员权限依据。

## 官方接口依据

- [Accessible.get_accessible_id](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.get_accessible_id.html)：通常为应用控件标识，不是微信账号 ID。
- [Accessible.get_relation_set](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/method.Accessible.get_relation_set.html)：查询对象间关系。
- [RelationType](https://gnome.pages.gitlab.gnome.org/at-spi2-core/libatspi/enum.RelationType.html)：`CONTROLLER_FOR`、`LABELLED_BY`、`POPUP_FOR` 等关系的定义。
