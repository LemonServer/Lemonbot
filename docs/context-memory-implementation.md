## 接口契约

接口位于 [unified 模型](../src/lemonbot/memory/unified/models.py) 与
[模块接口](../src/lemonbot/memory/unified/interfaces.py)。这些文件为无 I/O 的类型和 Protocol，
不从旧 memory 公共命名空间重新导出，也不在导入时加载 GPU 或启动 worker。

### 数据对象

| 对象 | 必需语义 |
|---|---|
| `ConversationScope` | channel＋已绑定 account_id＋精确 conversation_id＋private/group；不包含发送者 |
| `Message` | 原消息 ID、作者、时间、方向、内容片段、精确引用和出站状态；可选的 broker 原生消息定位符 |
| `MessagePart` | text/image/link/card/audio/video/file/unknown；未来类型可明确占位 |
| `SourceRef` | 完整 scope＋message_id＋可选 part_id；图片必须指定 part_id |
| `AttachmentRef` | 内容哈希、大小、类型、失效时间；不含路径、Base64 或访问授权 |
| `Observation` | 来源、提取版本、时间、可用内容或失败码；失败与正文分开 |
| `MemoryEntry` | 有来源、有作者、带版本的派生记忆；更正通过 supersedes 保留旧版本 |
| `RetrievalResult` | 同 scope 最多 20 个候选，含作者、来源、原因、索引版本和降级原因 |
| `ContextDecision` | standalone/related/clarify；最多 6 个候选 ID、当前观察和精确图片选择 |
| `ContextBundle` | 原始当前消息＋被选历史消息、观察和记忆；不自动携带完整对话 |

注意：`lemonbot.memory.ContextBundle` 仍是旧的模型消息容器。
新实现必须显式导入 `lemonbot.memory.unified.models.ContextBundle`，避免误替换旧调用点。

scope 使用现有绑定或校验后的内部引用，不从显示名生成，不改变现有事件身份算法。
入站归档主键沿用已验证的消息/事件标识；出站确认后的来源保留唯一 self 回读标识，
并另存与原事件/outbox 的关联，不把 UUID 或正文当成回读证据。
正文相同的不同消息仍是不同记录。part_id 在同一消息中必须唯一且稳定。

图片源文件的现行安全限制继续由附件层负责；URL 保存也不等于授予网络权限。
数据类型只验证结构、时间与基本边界；哈希校验、附件归属、来源存在性、有效期、
候选成员关系和 token 限制由后续归档器/组装器验证，不能以 Pydantic 验证替代。

### 服务边界

- `MessageArchive`：按 scope 精确读写；相同内容重复入库幂等，冲突报错；不得按正文去重。
  观察必须绑定真实存在的消息/片段。
  审计与已送达证据分开，UNKNOWN 不得变回待发送。
- `MemoryEntryStore`：阶段 6 的派生记忆存储，必须验证合格来源和更正的 scope；
  阶段 2 将其从 MessageArchive 分离，避免原始归档接口依赖尚未实现的整理模块。
- `ContextRetriever`：按当前消息 scope 先过滤，再检索；精确引用优先，结果上限 20。
- `RelevanceClassifier`：一次无工具调用，只输出选择，不重写原问题；无效结果不自动付费重试。
- `ContextAssembler`：验证当前轮候选及全部来源、作者、图片与预算，返回临时上下文。
  图片哈希不是授权，历史 URL 不授予新的访问权限。
- `EmbeddingWorker`：有界请求/响应与关闭接口；校验请求 ID、向量数量及版本，超时退出可恢复。
  每批最多 16 个不超过 4000 字符的片段，worker 分词后最多 512 tokens；长文先分块，
  不允许无声截断整篇内容。向量为 512 维有限数；归一化和请求响应匹配由实现验证。

实际调用始终由现有 pipeline 调度。归档、检索和 worker 都没有发送方法，
不新增独立接收循环、发送队列或工具权限。

## 配置与隔离规则

新增配置如下；旧配置没有此节时获得完全相同的默认值：

```toml
[context_memory]
enabled = false
archive_enabled = false
embedding_backend = "tensorrt"
```

阶段 1–4 曾对 `enabled=true` 无条件拒绝；阶段 5 已替换为启用条件检查：
必须使用 wechat_agent conversation runtime，同时启用 archive、关闭旧长期提取器、
至少允许两轮模型调用，并满足既有 DeepSeek Flash 及输入/输出上限要求。
`archive_enabled` 仅控制原始归档，单独启用不改变上下文选择。两个开关默认仍为 false。
本轮未改生产配置，阶段 8 验收前勿在运行服务中启用。
`embedding_backend="cpu"` 只接受人工显式选择；默认 CUDA/TensorRT，禁止静默回退。
GPU 不可用时阶段 4 可报告并降级为关键词＋近期候选，不等于启用了 CPU 模型。

目前运行服务仍按旧规则隔离：私聊或群＋发送者。
新流程开启后，同群共享记忆，所有片段和记忆保留作者；不同群、私聊、账号和 channel 隔离。
普通群消息只归档，真 @ 才回复；主动发言仍关闭。

后续迁移规则固定为：

- 保留旧 context_scope 和全部旧记录，不改写或删除。
- 通过原始消息 chat_id、作者和当前已验证账号绑定建立新 scope，不反解 HMAC 或猜测名称。
- 有合格来源的同群旧记录可归入共享群范围，但保留原作者。
- 仅有旧摘要、缺少可靠来源或账号/作者归属不明的条目不自动提升为共享记忆，报告排除数量。
- UNKNOWN/未确认 assistant 内容只保留审计；不成为检索证据、不触发整理或新付费重试。
- 附件沿用原私有目录与生命周期；备份和迁移不重新下载已失效附件。

### 旧记录迁移

[迁移器](../src/lemonbot/memory/unified/migration.py) 只在显式调用时导入，启动不会自动回填。
CLI 通过现有私有绑定与比较密钥验证目标，使用旧 inbox/messages 的 ID、作者、时间和
context_scope 交叉核验账号/会话归属。先导入入站来源，再验证 assistant 的唯一 ACK。

- 旧引用、图片或卡片原始结构不能恢复时，保存旧文本快照并标记
  `legacy_original_structure_unavailable`，不伪造原图、引用或网页正文。
- 旧 ACK 缺少原生消息定位符，使用持久回执 ID 作为迁移来源 ID，关联原 outbox；
  作者记为已绑定 bot 账号，不推测 canonical self 名称。后续无法建立的引用保持缺失。
- 未确认 assistant、归属不明、原入站来源缺失和未绑定范围明确计入排除原因。
  旧数据保留原位置；重复导入幂等，冲突报错，已提交批次可安全再次执行。

  关键词/语义权重 1，近期权重 0.25，精确引用分数确保优先。
- 候选最多 20 条，每消息最多 2 个单元，总 JSON 字符默认最多 16000。

- 无描述图片不可语义/全文检索，仅有明确图片追问时可成为近期待判断占位，或精确引用命中。

- 向量通过阶段 3 `chunks/embed` 获取，校验来源单元、请求 ID、数量、模型/后端/精度和单位向量。
  长单元的所有分词块参与归一化平均，不静默截断。默认每次刷新最多 256 块，未完成报告
  `semantic_index_incomplete`，再次刷新继续；向量版本改变时重新生成。
- GPU 初始化/运行/查询失败会显式降级为精确引用＋关键词＋近期候选，故障 worker 关闭，

### 新回答分支

完整说明见 [两阶段手册](context-flow.md)。主要组件：

- [TwoStageContextFlow](../src/lemonbot/memory/unified/flow.py)：只在新开关启用时进入。
  从 broker 绑定 scope 读取原始当前 Message，调用已有混合检索，再调用一次无工具、
  不思考的 DeepSeek Flash 分类。最多 20 条候选，按 token 上限裁减后只能选择实际提供的 ID。
  原问题不截断、不重写。分类只允许 standalone/related/clarify、最多 6 个候选 ID。

  当前观察只在 worker 证明实际构造了图片输入时接受，模型正文不能授予图片来源证明。
- [BoundImageResolver](../src/lemonbot/memory/unified/images.py)：核验原始/精确引用取图事件、
  单一附件归属、静态类型、10 MiB 上限、保留期限和哈希；不按最近图片或正文匹配。
  无唯一来源就拒绝。引用文字不能借用同消息的原图；新图不能借用旧图。
  每次回答模型请求前重验原图，过期或损坏只保留明确说明；每次最多一张原图。
  既有 worker 仍负责解码、清理和 HTTP Base64，不增大 IPC 限制。
- [PrepaidPair](../src/lemonbot/models/prepaid_budget.py)：在第一次请求前预留分类和首次回答
  的两个最大费用；各最多 8192 输入/512 输出，图片计入既有 1024 token 输入估算。
  同任务、同预算管理器消费原持久预留，逐次正常结算，不重复插入账本。
  未消费额度在结束/取消时释放，崩溃遗留仍按现有 unknown 恢复一次。
  普通回答为两次模型调用；工具续轮继续按原路径逐次预留，不承诺总共只有两次请求。
- EventPipeline 的新分支复用原回答/工具循环、策略、串行导航、inbox/outbox 和唯一发送路线。
  分类计入轮数和 token 统计；已有历史 URL 不授予 web.read 权限。
  无效分类不重试，退化为当前消息回答或澄清；传输/用量/预算不确定停止后续付费调用。
  新分支异常不可自动付费重试；UNKNOWN 的既有不可重发语义保持。
- runtime 只在开关开启时创建私有索引、独立 CUDA worker 与新 flow；关闭时不构建新图。
  GPU 不可用沿用阶段 4 的显式关键词/近期降级，不静默启动 CPU 模型。
  新流程和旧上下文/长期提取器互斥。

当前原文链接/卡片的 web.read 结果按精确 URL、消息和 part 保存为原始来源 Observation，
